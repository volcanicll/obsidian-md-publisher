# 发布弹窗改版方案：边填边看

> 状态：设计定稿，待实施。设计稿见会话可视化 `publish-modal-design.html`。

## 1. 结论

把「发布表单」和「公众号效果预览」合并成一个弹窗：左侧是一台 375px 的真机预览，右侧是紧凑的发布信息表单，发布前检查从独立弹窗降级为页脚状态条加可展开的结果抽屉。

用户不再需要在两个弹窗之间来回切换，改标题、换封面、开关评论都能即时反映在左侧预览里。

## 2. 现状与问题

当前 `PublishModal` 是竖向堆叠的 `Setting` 列表，`PublishPreviewModal` 是另一个独立弹窗：

| 问题 | 具体表现 |
| --- | --- |
| 看不到效果 | 改完标题、摘要、封面后必须点「预览效果」再开一个弹窗，且预览是打开瞬间的快照 |
| 表单太长 | 标题、作者、摘要、封面、原文链接、两个开关、发布方式各占一行 `Setting`，在 920px 宽度下右侧大片留白 |
| 封面只有一个路径框 | 只能手填 vault 路径，无法从本机上传；也看不出当前实际用的是「正文首图」还是「标题卡片」 |
| 校验是另一个弹窗 | 链接检查、敏感词检测要单独打开，回来时表单状态已经和检查结果脱节 |
| 正文封面不可控 | `show_cover_pic` 硬编码为 0，用户无法决定文章页顶部是否展示封面 |

## 3. 界面设计

### 3.1 骨架

```
┌──────────────────────────────────────────────────────────┐
│ 发布到公众号                                      ✕      │
│ 读书笔记 / 为什么写作.md                                  │
├───────────────────────────┬──────────────────────────────┤
│  文章页 | 分享卡片   375px │ 基本信息                     │
│  ┌─────────────────────┐  │  标题 / 作者 / 摘要           │
│  │ 9:41            …   │  │ 封面                         │
│  │                     │  │  缩略图 + 更换封面菜单        │
│  │ 标题                │  │  正文顶部显示封面 [开]        │
│  │ 作者 · 日期         │  │ 原文链接                     │
│  │ 封面                │  │ 互动                         │
│  │ 正文                │  │  开启评论 / 仅粉丝可评论      │
│  │ 阅读原文            │  │ 发布方式                     │
│  └─────────────────────┘  │  覆盖 / 新建 + 选择草稿       │
│                           │  目标草稿状态行               │
├───────────────────────────┴──────────────────────────────┤
│ （检查结果抽屉：只在有未通过项时出现）                     │
├──────────────────────────────────────────────────────────┤
│ 发布前检查  字段3/3  链接未检查  敏感词未检测   取消 发布 │
└──────────────────────────────────────────────────────────┘
```

尺寸：弹窗 `min(1040px, 94vw)`，高度 `min(840px, calc(100vh - 80px))`。头部与页脚固定，只有中间区域滚动，表单再长也不会把主按钮挤出屏幕。

### 3.2 左栏：真机预览

- 顶部两个页签：**文章页**、**分享卡片**。两者对应公众号里两个真实场景，用户最常确认的就是这两处。
- 375px 宽的手机框，带状态栏与圆点装饰，手机内部独立滚动。
- 文章页：标题（21px，长标题自然换行）、作者与日期、2.35:1 封面、正文（复用已渲染并内联样式的文章 HTML）、底部「阅读原文」。
- 分享卡片：微信会话气泡样式，标题最多两行后截断，右侧 56px 封面缩略图，下方一行摘要。标题或摘要超长时能直接看到截断效果。
- 宽屏下预览列 `position: sticky`，滚动右侧长表单时预览保持可见；容器窄于 900px 时自动改为单列并取消 sticky。

### 3.3 右栏：发布信息

| 分组 | 控件 | 说明 |
| --- | --- | --- |
| 基本信息 | 标题（必填）、作者、摘要 | 每个输入框右侧内嵌实时字数，超限变红；摘要为两行自适应文本域 |
| 封面 | 132×88 缩略图 + 来源角标 + 更换封面菜单 | 菜单四项：使用正文首图 / 从 vault 选择… / 上传本地图片… / 按标题生成卡片；下方一行说明当前来源的取图规则 |
| 原文链接 | 单行输入 | 对应 `content_source_url` |
| 互动 | 开启评论、仅粉丝可评论 | 关闭评论时自动禁用并取消「仅粉丝」 |
| 发布方式 | 下拉 + 选择草稿… + 状态行 | 覆盖模式下显示将覆盖的草稿标题与更新时间；未选目标时状态行变红并禁用主按钮 |

封面来源角标直接回答「现在用的是哪张图」：

- `正文首图`：取正文第一张图
- `assets/cover.png`：vault 内指定路径
- `本地上传`：本次临时选择的文件
- `标题卡片`：按标题生成的默认封面

### 3.4 页脚

- 左侧「发布前检查」按钮 + 三个状态胶囊：`字段 3/3`、`链接未检查`、`敏感词未检测`。
- 检查完成后胶囊变为结果摘要（如 `链接 1 条失败`、`敏感词 2`），颜色区分通过 / 警告 / 失败。
- 有未通过项时，页脚上方展开结果抽屉，只列未通过项；每条给出类别、具体内容与一个动作（复制链接 / 查看上下文）。抽屉可手动收起。
- 右侧「取消」与主按钮。主按钮文案随发布方式变化：`覆盖更新草稿` / `保存到草稿`。

### 3.5 状态规则

| 状态 | 触发条件 | 表现 |
| --- | --- | --- |
| 可发布 | 标题非空、三个字段均在长度限制内、覆盖模式已选目标 | 主按钮可用 |
| 字段不合规 | 标题为空或任一字段超限 | 对应计数变红，字段胶囊变警告，主按钮禁用 |
| 覆盖无目标 | 发布方式为覆盖但列表为空 | 状态行红字提示，主按钮禁用 |
| 发布中 | 图片上传 / 接口调用期间 | 主按钮与取消禁用，页脚显示进度文案 |
| 检查有失败 | 链接不可达或命中敏感词 | 胶囊变色，抽屉展开，**不阻止发布** |

## 4. 实现方案

### 4.1 文件结构调整

```
src/views/
  PublishModal.ts              改造：容器、页脚、发布流程（保留）
  PublishPreviewModal.ts       删除：能力并入 PublishModal
  publish/
    phone-preview.ts           新增：手机预览渲染与增量更新
    cover-picker.ts            新增：vault 选择器 + 本地文件读取
    publish-checks.ts          新增：链接 / 敏感词检查与结果模型
src/lib/wechat/
  publish-form.ts              新增：表单纯状态与字段校验
  draft-links.ts               扩展：封面来源指纹
```

`PublishPreviewModal` 只被 `PublishModal` 引用，没有外部入口，可以直接删除，同时删掉 `styles.css` 中 `.bm-md-phone`、`.bm-md-article-*`、`.bm-md-checks-*` 约 200 行旧样式。

### 4.2 表单状态

```ts
type CoverSource =
  | { kind: 'auto' }
  | { kind: 'vault'; path: string }
  | { kind: 'upload'; name: string; size: number; lastModified: number; data: ArrayBuffer }
  | { kind: 'generated' }

interface PublishFormState {
  title: string
  author: string
  digest: string
  contentSourceUrl: string
  needOpenComment: boolean
  onlyFansCanComment: boolean
  showCoverInBody: boolean
  cover: CoverSource
  publishMode: 'new' | 'update'
  draftLink: DraftLink | null
}
```

纯函数 `computeFieldState(state)` 返回每个字段的字数、是否超限、是否必填缺失，以及整体 `ready`。这样校验逻辑可以单测，UI 只负责把结果映射成样式。

### 4.3 封面来源

`coverKeyFor` 目前只接受「显式路径 / 正文首图 / 标题」。改为先由来源计算指纹，再交给原有复用逻辑：

```ts
function coverKeyForSource(
  source: CoverSource,
  firstBodyImagePath: string | null,
  title: string
): string
```

| 来源 | 指纹 | 说明 |
| --- | --- | --- |
| vault | `file:<path>` | 与现有行为一致 |
| 本地文件 | `upload:<name>:<size>:<lastModified>` | 同一文件再次选择时可复用永久素材 |
| 正文首图 | `auto:<firstBodyImagePath>` | 现有逻辑 |
| 标题卡片 | `generated:<title>` | 标题变化即重新生成 |

`resolveCover` 改为按 `kind` 分支：

- `vault`：`resolveVaultImageFile` + `readImageFromVault` + `compressImage`
- `upload`：直接用内存中的 `ArrayBuffer` + `compressImage`
- `auto`：沿用 `results[0]`
- `generated`：`generateDefaultCover(title)`

内存中的上传文件只保留到本次发布结束，关闭弹窗时清空，并 `URL.revokeObjectURL` 释放预览地址，不写入 vault。

### 4.4 真机预览

- 打开弹窗时用现有 `loadContent()` 取一次 HTML，`resolveLocalImageSrcs` 解析本地图片后挂到手机正文容器。
- 标题、作者、日期、摘要、分享卡片、字数只更新文本节点，不重新解析 HTML。
- 用户输入用 `requestAnimationFrame` 合并到一帧内更新，避免逐字输入时抖动。
- 正文容器限制高度并独立滚动，长文不会把弹窗撑高。
- 主题样式已由渲染流程通过 juice 内联，手机内不需要再注入主题 CSS；只需保证容器宽度为 375px，与公众号阅读宽度一致。

### 4.5 发布前检查

`publish-checks.ts` 暴露一个轻量控制器：

```ts
interface CheckReport {
  links: LinkCheckResult[]
  words: SensitiveHit[]
  ranAt: number | null
}

async function runChecks(html: string, form: PublishFormState): Promise<CheckReport>
```

- 链接与敏感词并行执行，任一完成先更新对应胶囊，不互相等待。
- 链接范围：正文 `<a href>` 加原文链接字段。
- 敏感词范围：标题、摘要、正文纯文本。
- 结果只提示不拦截，与现有策略一致；图片上传失败仍然中止发布。
- 「发布前检查」按钮在检查期间禁用并显示「检查中…」。

### 4.6 正文封面开关

新增设置项 `showCoverInBody`，默认开启，映射到 `show_cover_pic`。这是行为变化：旧版本固定为 0，升级后文章顶部会开始显示封面。需要：

- 在 CHANGELOG 中明确写出；
- 设置页「发布默认值」增加同名开关，弹窗内可逐次覆盖；
- 关闭时手机预览同步隐藏封面，但封面仍用于分享卡片。

### 4.7 发布流程改动

`publish()` 的骨架、覆盖更新与三类失败兜底保持不变，只改三处：

1. 封面读取从 `this.coverPath` 改为 `this.form.cover`；
2. `buildArticle` 的 `show_cover_pic` 取自表单；
3. 进度文案从独立进度条改到页脚胶囊区域，避免弹窗内再出现一块会跳动的区域。

发布期间仍然锁定 `updating` 与 `target`，中途切换发布方式不会造成「以为在覆盖，实际新建」。

### 4.8 样式

新增 `.bm-md-pm-*` 命名空间，全部使用 Obsidian 变量（`--background-primary`、`--text-normal`、`--interactive-accent` 等），不引入 `light-dark()`，主题切换由 Obsidian 自身负责。

关键点：

- 根容器 `container-type: inline-size`，用容器查询而不是视口查询，弹窗被嵌在侧栏时也能正确降级；
- 中段 `overflow-y: auto`，头部与页脚 `flex-shrink: 0`；
- 窄于 900px 改单列，预览取消 sticky；
- 窄于 420px 手机占满宽度，封面缩略图改为通栏。

### 4.9 测试

新增纯函数测试：

- `computeFieldState`：空标题、各字段边界值、emoji 按码点计数、可选字段留空；
- `coverKeyForSource`：四种来源、标题变化、同一本地文件复用；
- 检查结果摘要：全部通过、部分失败、命中敏感词三类文案。

现有 `draft-links`、`wechat-client`、`main` 测试不受影响；`coverKeyFor` 保留原签名，新增函数独立测试。

手工验收清单：

1. 宽屏与窄屏各看一遍，无横向滚动条，页脚始终可见；
2. 输入长标题，预览换行、计数变红、主按钮禁用；
3. 封面四种来源逐一验证，上传本地图后预览与发布结果一致；
4. 覆盖模式未选目标时主按钮禁用，选择后恢复；
5. 检查出失败链接与敏感词时抽屉展开、胶囊变色，仍可发布；
6. 深色 / 浅色主题下无对比度问题。

### 4.10 分阶段实施

| 阶段 | 内容 | 可独立验收 |
| --- | --- | --- |
| 1 | 新骨架、双栏布局、表单与实时预览 | 是 |
| 2 | 封面菜单、本地文件上传、正文封面开关 | 是 |
| 3 | 页脚检查胶囊与结果抽屉，删除旧预览弹窗 | 是 |
| 4 | 样式收尾、单测、CHANGELOG / README / 使用文档 | 是 |

### 4.11 风险

| 风险 | 处理 |
| --- | --- |
| Obsidian 弹窗自身高度限制 | 根容器设 `max-height: calc(100vh - 80px)`，内容区滚动，不依赖浏览器默认行为 |
| sticky 在滚动容器内失效 | 已用同等结构做浏览器验证；单列断点直接取消 sticky |
| 本地大图占内存 | 选择后立即压缩再预览；发布结束清空 ArrayBuffer 与 object URL |
| 删除预览弹窗影响用户习惯 | 功能等价且更强，在 CHANGELOG 中说明「预览效果」入口并入发布弹窗 |
| `show_cover_pic` 默认值变化 | 设置项可关，升级说明中明确提示 |

## 5. 验收标准

- 点击「发布」只出现一个弹窗，左侧手机预览与右侧表单同时可见；
- 修改标题、作者、摘要、封面、评论开关，预览即时更新，无闪烁；
- 封面可以从正文首图、vault、本地文件、标题卡片四种来源中选择，并显示当前来源；
- 发布前检查在弹窗内完成，结果不阻止发布；
- 覆盖更新与新建两种模式的行为、兜底逻辑与现版本完全一致；
- 宽屏 / 窄屏 / 深色 / 浅色均无布局破损；
- lint、typecheck、单测、构建全绿。
